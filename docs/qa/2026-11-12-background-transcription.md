# 녹음 내용을 글로 옮기는 일을 저장 뒤 백그라운드로 넘김

## 대상
녹음을 멈추면 작성 화면이 그 자리에서 바로 글로 옮겼습니다. 녹음 길이의 절반쯤 걸렸고 "녹음 길이의 절반쯤 걸려요"라고 안내했기 때문에, 사용자는 기다려야 한다고 느꼈습니다. 이제 작성 화면은 글로 옮기지 않고, 저장한 뒤 `AnalysisWorker`가 백그라운드에서 옮깁니다. 이 워커는 원래도 transcript가 비어 있으면 직접 옮기도록 되어 있었습니다.

| 파일 | 변경 내용 |
|---|---|
| `ui/newentry/NewEntryViewModel.kt` | 화면에서 글로 옮기던 기능을 지움: `transcribe()`, `transcript`·`transcribing`·`transcriptProblem` 상태, `clearTranscript()`, 재시도 상수 |
| `ui/newentry/NewEntryScreen.kt` | `TranscriptPreview`를 지우고 녹음 아래에 안내 한 줄을 둠. 미지원 기기 / 10분 초과 / 일반 세 경우로 나뉨 |
| `ai/Transcriber.kt` | 엔진을 한 번에 하나만 쓰도록 `Mutex` 추가(대기 시간은 예산에 포함하고, 끝내지 못할 녹음은 시작하지 않음). `isSupported()` 추가. 실패 문구를 해요체로 통일 |
| `ai/AnalysisWorker.kt` | BUSY일 때 다시 시도하면서 남은 예산만 쓰도록 함. 주석 수정 |
| `ui/home/HomeScreen.kt` | 기록 카드에 실패 상태 "말한 내용을 글로 옮기지 못했어요" 표시 |

## 정상으로 확인된 동작
- 저장하면 `analysis`의 기본값이 PENDING이라 홈과 상세 화면 모두 바로 "말한 내용을 글로 옮기는 중이에요"를 보여 줍니다.
- 작성 화면이 하던 일(BUSY 재시도, 언어팩, 10분 초과, 미지원, 실패 시 '다시 분석')을 워커가 모두 맡습니다. 다시 시도할 수 있는 실패에서는 WAV를 압축하지 않고 남겨 둡니다.
- WAV는 기록이 압축본을 가리키도록 update한 뒤에야 지웁니다.
- 글로 옮기는 도중 앱이 종료되면 WorkManager가 다시 실행합니다. 압축과 내보내기는 그 뒤에 하므로 WAV는 남고 중복도 생기지 않습니다.
- `withLock`은 취소, 타임아웃, 정상 종료 어느 경우에도 락을 풀고, 다시 들어오는 경로가 없어 교착되지 않습니다.
- 사용자가 상세 화면에서 직접 쓴 글이 있으면 워커의 결과보다 그 글을 우선합니다.

## 직접 검증한 것
- 수정할 때마다 `gradlew.bat assembleDebug` 빌드가 통과했습니다.

## 아직 확인하지 못한 것
- 실기기에서의 동작: 녹음을 연달아 저장했을 때 순서대로 처리되는지, 앱이 백그라운드에 있을 때 워커의 온디바이스 인식이 동작하는지, 백그라운드에서 언어팩 다운로드를 요청했을 때 실제로 받아지는지
- 10분 제한으로 워커가 중단된 뒤 다시 예약되는 동작
