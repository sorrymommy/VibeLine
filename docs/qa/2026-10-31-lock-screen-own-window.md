# 잠금 화면 위에서 대화상자를 PIN 없이 조작할 수 있는 문제

- 날짜: 2026-10-31
- 대상 기능: PIN 잠금 화면과, 잠금이 걸릴 때 이미 열려 있거나 나중에 뜨는 대화상자
- 대상 파일: `ui/lock/LockScreen.kt`, `ui/lock/PinSetupDialog.kt`, `MainActivity.kt`, `ui/newentry/NewEntryScreen.kt`
- 관련 문서: [프로세스가 정리된 뒤 다시 열면 PIN 잠금을 건너뛰는 문제](2026-10-30-pin-relock-after-process-death.md)에서 남긴 기존 Major 2건을 해결

## 원인

잠금 화면이 액티비티 창 안의 일반 오버레이였다. Compose `Dialog`는 별도 창이라 그 위에 뜬다. 기록 상세에서 삭제 확인을 연 채 나갔다가 5분 뒤 돌아오면, 잠금 화면 위에 대화상자가 그대로 남아 "지우기"가 조작 가능한 상태였다(수정 전 에뮬레이터에서 재현). 잠금 중 접근성 트리에도 뒤쪽 타임라인이 그대로 나왔다.

## 수정

- `LockScreen`을 전체 화면 `Dialog` 창으로 옮겼다. 이미 열린 대화상자보다 나중에 뜨므로 그 위에 온다.
- 창이 뜨기 전의 틈을 막으려고 액티비티 창에 불투명 덮개를 둔다. 덮개가 터치와 뒤로 가기도 받는다.
- 창 애니메이션을 꺼서 아래 대화상자가 비치는 시간을 줄였다.
- 시작 화면(태그라인)은 잠금 창이 덮어도 보이도록 양쪽 창에 그린다.
- `moveChoice`는 위치 조회 뒤 비동기로 떠서 잠금 위로 올라올 수 있으므로, `NewEntryScreen`이 `appLocked`를 받아 잠금 중에는 띄우지 않는다. 상태는 유지되어 해제하면 나타난다.
- 잠금 화면의 뒤로 가기를 `finish()`에서 `moveTaskToBack(false)`로 바꿨다. 작성 중인 초안이 지워지지 않는다. 다른 앱 위에서 실행된 인스턴스(태스크 루트가 아님)만 `finish()`한다.
- 모든 `PinPad` 호출이 `Dialog` 안으로 들어가 `PinPad`의 터치 차단을 지웠다. 대신 `PinSetupDialog`에 `dismissOnClickOutside = false`를 지정했다.

정상으로 확인된 동작(QA 판단):
- 대화상자 중 탭 없이 뜨는 것은 `moveChoice`뿐이다. 나머지는 사용자 입력으로만 켜지고 `remember`라 회전하면 사라진다.
- 덮개는 이벤트를 소비하지 않아도 위쪽 형제라 아래 NavHost로 전달되지 않는다.
- 해제 후 화면과 입력 내용은 유지된다(NavHost를 컴포지션에서 빼지 않음). 5분 넘게 카메라를 쓰고 돌아온 결과도 유지된다.
- 실패 대기 시간은 저장소 값이라 회전이나 프로세스 복원으로 풀리지 않는다.

## 직접 검증한 것

- `gradlew.bat assembleDebug` 빌드 성공(최종 코드).
- 에뮬레이터(Pixel 8, API 35). 대기는 실제 시간으로 진행했다. `moveChoice`만 2차 수정 전 빌드에서 확인했고, 나머지는 최종 빌드다.

## 아직 확인하지 못한 것

- 재잠금 순간 이전 대화상자가 몇 프레임 노출되는지(화면 녹화 필요). 위 수용한 위험의 실제 크기다.
- 키보드가 올라온 채 재잠금되어 복귀할 때의 동작.
- TalkBack 실사용. UI 덤프로만 확인했다.
- 다른 앱에서 실행했을 때의 뒤로 가기, 화면 고정 상태.
- API 26~30과 실기기(Galaxy S23), 3버튼 내비게이션에서의 삽입 영역과 아이콘 색.
- 비동기 `moveChoice` 경로(잠긴 뒤 위치 결과 도착). 같은 조건문을 지나지만 그 순서로 재현하지는 못했다.
