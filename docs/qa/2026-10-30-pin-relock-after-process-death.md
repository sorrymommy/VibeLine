# 프로세스가 정리된 뒤 다시 열면 PIN 잠금을 건너뛰는 문제

- 날짜: 2026-10-30
- 대상 기능: 백그라운드에 5분(`AppLock.RELOCK_AFTER_MS`) 넘게 있다가 돌아올 때의 PIN 재잠금
- 대상 파일: `MainActivity.kt`
- 관련 문서: [사진을 찍고 나면 카메라가 다시 열리는 문제](2026-10-30-camera-relaunch-after-photo.md)의 별건 Major를 해결

## 원인

앱을 떠난 시각 `stoppedAt`이 일반 필드여서 프로세스가 끝나면 0으로 돌아간다. 복원될 때 `locked`는 저장해 둔 `false`이고 `stoppedAt`이 0이라 `onStart`의 재잠금 조건이 걸리지 않는다.

수정 전 빌드를 에뮬레이터에서 재현했다. 잠금을 푼 뒤 홈으로 나가 프로세스를 끝내고 320초 뒤 최근 앱에서 열자, 새 프로세스로 복원되면서 PIN 없이 이전 화면이 나왔다.

## 수정

- `stoppedAt`을 `onSaveInstanceState`에 저장하고 `onCreate`에서 복원한다. 판단은 기존처럼 `onStart`가 하며, 조건은 `awayTooLong`으로 분리했다.
- `onStart`에서 판단한 뒤 `stoppedAt`을 지운다. 지우지 않으면 복귀하고 5분 뒤 화면을 회전할 때 예전 시각이 복원되어 쓰는 중에 잠긴다.
- API 26·27은 `onSaveInstanceState`가 `onStop`보다 먼저 불리므로, 회전이 아닌데 `stoppedAt`이 비어 있으면 저장 시점의 시각을 넣는다.
- 시각 기준을 `System.currentTimeMillis`에서 `SystemClock.elapsedRealtime`으로 바꿨다. 기기 시계를 바꿔도 판단이 흔들리지 않는다. 저장 상태는 재부팅 후 남지 않아 재부팅 뒤에는 콜드 스타트로 잠긴다.

정상으로 확인된 동작(QA의 코드 추적, 수명주기 순서는 플랫폼 지식 기반):
- 포그라운드 회전·멀티윈도 전환은 `stoppedAt` 0이 저장되어 잠기지 않는다. 멀티윈도에서 포커스만 잃으면 `onStop`이 없어 타이머가 시작되지 않는다.
- 최근 앱에서 제거, 강제 종료, 재부팅, 뒤로 가기로 종료, 포그라운드 크래시는 저장 상태가 없어 콜드 스타트로 잠긴다.
- PIN 해제 직후에는 `onCreate`와 `onStart`의 `isEnabled` 검사로 잠기지 않고, PIN 설정 직후에는 다음 이탈부터 판단이 작동한다.
- 5분 넘게 카메라를 쓰고 돌아와도 결과는 잠금 뒤에서 처리되어 사진이 유지된다.
- 외부 앱이 `MainActivity`를 직접 실행하면 새 인스턴스라 잠긴다.

위 Major 2건은 [2026-10-31 문서](2026-10-31-lock-screen-own-window.md)에서 수정했다.
